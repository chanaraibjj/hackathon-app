# 00: 事前練習用テーマ予想(本番では開かない)

本番前に 01-A→01-D を通しで回す練習用。タイマーで15分(A:3分 / B:4分 / C:3分 / D:5分)を計り、シート記入まで到達する。
**特に「つながる」「境界」「残す」「なくす」「気づく」で練習推奨。**

## なぜ練習するか(審査基準から逆算)

ベース評価は **インパクト5点+実在感5点**。さらに**動作・公開・技術選定・システム連携で最大8点加点**。
つまり勝負は、抽象テーマを「**実際に誰かが使いたくなる具体的な体験**」へ変換する速さと、完成して公開すること。
アイデアの奇抜さ単体では勝てない。

さらに発表Slide 1は「テーマをどう解釈したか / なぜその解釈を選んだか(捨てた選択も含めて)」を説明する構成。
**解釈の思考プロセス自体が審査対象**なので、練習でもシートのOTHER OPTIONS / WHY CUTまで必ず書く。

## ワンツイストの実演(01-Aの「他チーム予測→ずらす」はこれをやっている)

テーマ「境界」の場合:

- **多くのチームが出しそう**: AIで言語の境界をなくす翻訳アプリ(ありがち)
- **一段ひねる**: 境界 → 人間とAIの境界 →「これ、誰が考えた?」
  AIと人間が共同で文章・画像・コードを作ったとき、どこまで人間でどこからAIかを可視化するサービス。テーマとの結びつきを説明しやすく、デモもできる
- **別方向**: 境界 → 旅行者と地元民の境界 →
  観光客がカメラを向けると、AIが「観光情報」ではなく地元民ならどう見るかを教えてくれるアプリ

## 解釈チェーンの実演(テーマ→すぐアプリを考えない)

テーマ「残す」の場合:

```
残す
→ 記憶を残す / 文化を残す / 判断理由を残す / 声を残す / 失敗を残す
→「失敗を残す」を採用
→ AIが自分の失敗経験を記録して、次に同じ状況になったとき警告してくれるサービス
```

順番は常に: **テーマ → 解釈を広げる → 人間の課題に変換 → 2時間でデモできるものを選ぶ**。
