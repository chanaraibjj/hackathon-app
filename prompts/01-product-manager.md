# 01: Product Manager(14:10–14:25 の15分を4段階で)

役割分担: **AIは生成する。人間は選択する。**
テーマ発表中(14:00–14:10)は聞く+メモに専念。開発開始と同時に01-Aを貼る。

| 時刻 | 段階 | 使う |
|---|---|---|
| 14:10–14:13 | INTERPRET(解釈10個) | 01-A |
| 14:13–14:17 | IDEATE(上位3解釈×3案) | 01-B |
| 14:17–14:20 | SELECT(採点→**人間が決定**) | 01-C+5問 |
| 14:20–14:25 | DEFINE(MVP・技術判断・シート記入) | 01-D |

---

## 01-A: テーマ解釈(14:10–14:13)

```
あなたはハッカソンのプロダクト戦略担当です。

当日のテーマは、

「{{THEME}}」

です。主催者の補足・制約は以下:

{{補足・制約・キーワード・審査上重要そうな発言のメモ}}

このテーマは抽象的で正解はありません。
解釈そのものも作品の一部です。
(公式も「解釈の幅は広め。正解はひとつではありません。あなたなりの解釈で、スタートを切ろう」と明言しています)

まだプロダクト案は出さないでください。

まずテーマ解釈だけを行ってください。

最初に、多くのチームが最初に思いつきそうな解釈を3つ予測して、
一言ずつ挙げてください。

以降の10個の解釈は、この3つをそのまま採用しないでください。
同じ方向を扱う場合は、USERか「日常で起きる具体的な瞬間」を
変えて差別化してください。

以下を含め、互いに異なる解釈を10個出してください。

- 文字通り
- 人間・感情
- 日常生活
- 社会・制度
- 地域
- 時間
- 空間
- 情報
- テクノロジー
- 比喩・意外

さらに、

- 増やす
- 減らす
- なくす
- 見えるようにする
- 逆転する

という方向も考慮してください。

10個のうち2つは、テーマを全く無関係な領域
(例: 料理、天気、スポーツ、生き物、ゲーム)に一度置き換えて、
そこで見つかる構造を日常の問題に持ち帰る形で作ってください。

テーマが動詞や短い語の場合は、対象を入れ替えた派生を
素早く並べてから強いものを解釈に採用してください。
(例:「残す」→ 記憶を残す / 文化を残す / 判断理由を残す /
声を残す / 失敗を残す)

各解釈について、

1. 解釈名
2. どう捉えたか
3. 日常で起きる具体的な瞬間
4. 関係する具体的なUSER
5. USERの問題
6. 意外性
7. テーマとの納得感
8. 120分でプロダクト化可能か

を出してください。

最後に、

王道
人間
社会
意外

から最も強いものを1つずつ選んでください。

まだ具体的なプロダクト機能は考えないでください。
```

## 01-B: アイデア生成(14:13–14:17)

```
選ばれた解釈から、特に強い上位4解釈を使います:

{{上位4解釈(01-Aの出力から。自分の直感で入れ替えてよい)}}

各解釈からプロダクト案を3つずつ出してください。

各案は、

- ONE-LINER
- 1 USER
- 1 PROBLEM
- 1 CORE EXPERIENCE
- 1 WOW MOMENT
- 最小MVP(最低何が動けば成立?)

だけ出してください。

機能一覧は不要です。

AIを無理に使わないでください。
技術選定はまだ行いません。

「何を作れるか」ではなく、
「ユーザーが何を体験するか」を優先してください。
```

## 01-C: アイデア比較(14:17–14:20)

```
前提: 本大会の審査は「インパクト5点+実在感5点」に加え、
動作・公開・技術選定・システム連携で最大8点が加点されます。
抽象テーマを「実際に誰かが使いたくなる具体的な体験」に
変換できているかを最重視して採点してください。

全アイデアを以下で5点満点評価してください。

- テーマとのつながり
- USERの明確さ
- PROBLEMの強さ
- CORE EXPERIENCE
- WOW MOMENT
- 3分デモ映え
- 120分実装可能性
- 実在感

上位3案を選んでください。

さらに合計点とは別に、

「3分発表で最も印象に残る案」

を1つ選んでください。

各案について、
最大の強みと最大のリスクを一言ずつ示してください。
```

**→ 決定は人間(14:20 DECISION DEADLINE)。上位3案をこの5問で判定:**
1. 一言で説明できる? 2. 困っている人を想像できる? 3. 30〜50秒でデモできる?
4. 結果を見た瞬間に価値が分かる? 5. 25分程度で最初のMVPを作れそう?
**4/5以上YESで採用可。迷ったらWOWが強い方→同じなら実装が簡単な方。以降は変更禁止。**
(公式メッセージ:「完璧なアイデアでなくていい。まず方向性を決めることが大事」「**小さく決めて、大きく動く**」— 迷ったら即断が公式の推奨)

---

## 01-D: 採用後MVP+技術判断(14:20–14:25)

```
採用案: {{案の名前}}

採用案を120分ハッカソン用MVPにしてください。

以下を確定してください。

THEME
INTERPRETATION
WHY
OTHER OPTIONS
WHY CUT

OTHER OPTIONSには最後まで迷った別の解釈・案を2つ、
WHY CUTにはそれを選ばなかった理由を書いてください。
審査は「テーマをどう解釈したか」「何を選び、何を捨てたか」も
評価対象で、発表Slide 1でこの内容をそのまま使います。

1 USER
1 PROBLEM
PRODUCT
ONE-LINER
1 CORE EXPERIENCE
VALUE
DIFFERENCE
WHY IT WORKS
1 WOW MOMENT

USER STORY

30〜50秒のDEMO FLOW

USER ACTION
PROCESS
RESULT

MUST 最大3つ
OPTIONAL
CUT

MUSTは「3分発表のDemoに登場するか?」で逆算してください。登場しない機能は入れないでください。

さらに、

AI
External API
DB

について、

必須
あると良い
不要

で判定してください。

「あると良い」は原則MVPから外してください。

最も単純な実装構成を提案してください。
何も必要なければ「USER → UI → LOCAL LOGIC → RESULT → WOW」の最小構成とし、
Dummy AI / Mock / Demo Modeも作らないでください。
AIが必須の場合のみ、Real AIより先にDummy AIで体験を完成させる前提にしてください。

最後に、上記の確定内容で THEME_DECISION_SHEET.md を(TECH CHECK欄まで)すべて埋めて保存し、
実装タスクの順番付きリスト(各タスクに目安時間、合計25分以内=14:50のMVP締切)を出してください。
```
